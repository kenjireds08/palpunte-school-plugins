# school-starter プラグイン 変更履歴

最新が上。`/school-starter:setup` の更新時メッセージは、このファイルから
「前回入れていたバージョンより新しい節」を読み出して表示する。

各バージョンの見出しは `## vX.Y.Z — YYYY-MM-DD` 形式で固定（setup が機械的に拾うため崩さないこと）。
直近バージョンは詳細 bullet、それ以前は1行要約。元データは Notion「更新履歴」。

## v1.26.1 — 2026-08-26
- **Claude が「覚えておくためのメモ」を新しく作れなかったのを修正**。安全のための自動チェックが、余計な .md ファイルがプロジェクトに散らかるのを防いでいるのですが、その仕組みが**メモの保存先まで巻き込んで止めていました**。すでにあるメモの更新はできていたので気づきにくい不具合でした。受講生の方からのご報告で判明しました
- あわせてお願いです。**Claude が「このチェックに引っかかったので別のやり方で回避します」と言い出したら、止めてください**。チェックは AI にうっかりやらせないための壁なので、迂回されると意味がなくなります。そういう場面に出会ったら、回避させずに教えていただけると、今回のように仕組み側を直せます

## v1.26.0 — 2026-08-22
- **「図つきで説明して」が一言で頼めるようになった（`eli5` スキル新設）**。`/eli5 〇〇` と打つか、「図解して」「クライアントに説明したい」「引き継いだこのコードが何をしているのか教えて」のように話しかけると、その分野を何も知らない人に向けた説明ページを1枚作ってブラウザで開く。文章だけの説明より、相手が理解するまでの時間が短くなる。お客さんへの仕様説明、引き継いだ案件の理解、不具合が起きた経緯の振り返りに使える
- **図の描き方を決まり事にした**。箱のラベルは「日本語の呼び名＋実体を小さく」の2段、矢印には必ず動詞、実線は主な流れで点線は補助、色はモノトーン＋1色だけ。さらにサイト・データベース・定期実行・クラウド・人・外部サービス・自動で動くものを、それぞれ決まった絵記号で描き分ける。同じ長方形を並べただけの図にならないための指定
- **実装プランの「判断用の1画面ページ」にも、図が必ず入るようになった**。これまで文章だけでも通っていたが、全体像の図を先頭に置くようにひな形と案内文を変えた。プランを見せられた側が、読み込まなくても何をしようとしているか分かる
- **説明ページはライトテーマ固定**。相手の環境がダークでも崩れないようにするため、ダークモード対応は付けない

## v1.25.2 — 2026-08-08
- **納品前チェックの「連携アプリの棚卸し」で、Vercel のリンクが 404 になっていたのを修正**。Vercel 側がページを移したため、直リンクではなくダッシュボードから辿る手順に変えた。GitHub 側の一覧で同じ連携を確認できていれば、そちらで代えてよいことも明記

## v1.25.1 — 2026-08-05
- **納品前チェックの項目2で「キーが漏れています」と誤判定されるのを修正**。`.env.example` は中身がダミー値のテンプレートなので git に入っているのが正常なのに、これを検出して「API キーを全部再発行してください」と案内していた。テンプレート類を除外したうえで、判定の手前に「出てきたファイル名をまず見る」確認を入れた
- **Vercel のログ確認手順を、ブラウザのダッシュボード操作に変更**。実機検証 4-3 がターミナルのコマンド（`vercel logs`）を案内していたが、このコースの `CLAUDE.md` は Vercel CLI を使わない方針なので、指示が食い違っていた
- **無料プランの停止対策（項目10）の判定を実態に合わせた**。毎日決まった時刻に動く仕組みがあって、それがデータベースを読みに行っていれば停止は起きない。「対策を新しく足す」ではなく「すでに作ったものが対策になっている」ことを確認できるようにした

## v1.25.0 — 2026-07-31
- **お金の事故を防ぐ `cost-guard` スキルを新設**。「毎朝自動で動かしたい」「cron で定期実行」「API キーを使う」「料金が心配」等の発話で自動発動し、①上限金額を先に決める ②動くきっかけを絞る ③AI に最後まで任せない ④終わったら止める、を1つずつ確認する。定額サブスク（Claude Code 本体）と従量課金（API・自動レビュー・Actions）の違いを最初にはっきりさせるので、「どこまでが安全でどこからが青天井か」が分かる。自動レビューの暴走で1日150万円の請求が出た実例をもとにした内容
- **実装プランに「判断用の1画面ページ」を作る流れを追加**。`docs/plans/` に実装プランの .md を作ると Hook が検知し、Codex のレビューが終わったあと・実装に入る前に、同じ内容を1画面の HTML に要約させて見せるようになった。専門用語・ファイル名を書かず「決めてほしいこと（最大3つ）／何が変わるか／触る範囲／リスクと戻し方」だけを載せる。プランの .md は分量も専門用語も多く、読み切れないまま承認してしまう問題への対策（技術的な妥当性は Codex が担当し、人は「これは自分が求めているものか」を判断する、という分担）。ひな形も同梱
- **レビューの最後に「自分で見てほしい3点」を必ず案内するようにした**。①頼んだとおりのものか ②空のまま送信・長い文字・連打を試したか ③お客さんに説明できるか。AI のレビューはコードの中しか見ておらず「そもそも何を作りたかったか」は見ていない。AI 2段階の approve が揃うほど「AI が見たから大丈夫」の油断が育つため、最後は人に戻す
- ステータスラインの説明に出てくるモデル名の表示例を現行世代に更新（表示自体は元から自動追従なので動作の変更はなし）

> 💡 このバージョンから、**新機能は `/plugin` の Update だけで反映される場所**（スキル・Hook・コマンド）に置いています。`~/.claude/rules/` へコピーする方式は setup を再実行しないと届かないためです。
