# 開発ルール

## 開発原則
- 要件定義を最優先
- 既存パターンを踏襲
- テスト実行後にデプロイ
- 複雑なタスクは3-5段階に分割
- エラー発生時は最大3回まで試行
- 依頼された内容のみ実装し、過剰な機能追加・抽象化をしない
- 推測でコードを提案せず、必ず該当ファイルを確認してから回答する
- **判断にだけ AI を使う**: 分類・要約・抽出には Claude を使ってよい。ただし**決定論的処理**（リトライ判定、ステータスコード分岐、フォーマット変換）はコードで書く。コードで答えられる問いはコードで答えさせる
- **規約衝突は平均化せず surface する**: コードベース内に矛盾する 2 つのパターンが共存している場合、両方を満たそうとして混ぜたコードを書かない。**新しい方・テスト済みの方を選び、もう一方を cleanup フラグとして報告**する
- **Fail loud**: 「完了」「pass」「成功」を簡単に言わない。スキップしたレコード・実行しなかったテスト・確認していないエッジケースは**明示的に surface**する。不確実性は隠さず可視化する

**詳細:** CLAUDE.md 設計の全体像は `/school-starter:claude-md` スキルで参照可能（Karpathy 4 ルール + @mnilax 追加 8 ルール / 30 codebase × 6 週間でミス率 41% → 3% の実証データ）。

## コード実装前の必須確認
- 類似の既存コードを確認
- コードスタイル・命名規則を踏襲
- 既存のユーティリティを活用

## セキュリティ
- .envファイルはコミットしない
- APIキーはVercel環境変数で管理
- 認証情報をログに出力しない

## テストコマンド
```
npm run lint       # lint
npm run typecheck  # 型チェック
npm test           # テスト
npm run build      # ビルド
npm run check      # 一括実行（あれば）
```

## 検証ルール
実装完了後は検証コマンドを実行し、エラーがなくなるまで修正すること
