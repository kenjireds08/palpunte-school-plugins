# 開発ルール

## 開発原則
- 要件定義を最優先
- 既存パターンを踏襲
- テスト実行後にデプロイ
- 複雑なタスクは3-5段階に分割
- エラー発生時は最大3回まで試行
- 依頼された内容のみ実装し、過剰な機能追加・抽象化をしない
- 推測でコードを提案せず、必ず該当ファイルを確認してから回答する
- **判断にだけ AI を使う**: 分類・要約・抽出には Claude を使ってよい。ただし**決定論的処理**（リトライ判定、ステータスコード分岐、フォーマット変換）はコードで書く。コードで答えられる問いはコードで答えさせる
- **規約衝突は平均化せず surface する**: コードベース内に矛盾する 2 つのパターンが共存している場合、両方を満たそうとして混ぜたコードを書かない。**新しい方・テスト済みの方を選び、もう一方を cleanup フラグとして報告**する
- **Fail loud**: 「完了」「pass」「成功」を簡単に言わない。スキップしたレコード・実行しなかったテスト・確認していないエッジケースは**明示的に surface**する。不確実性は隠さず可視化する

**詳細:** CLAUDE.md 設計の全体像は `/school-starter:claude-md` スキルで参照可能（Karpathy 4 ルール + @mnilax 追加 8 ルール / 30 codebase × 6 週間でミス率 41% → 3% の実証データ）。

## コード実装前の必須確認
- 類似の既存コードを確認
- コードスタイル・命名規則を踏襲
- 既存のユーティリティを活用

## セキュリティ
- .envファイルはコミットしない
- APIキーはVercel環境変数で管理
- 認証情報をログに出力しない

## テストコマンド
```
npm run lint       # lint
npm run typecheck  # 型チェック
npm test           # テスト
npm run build      # ビルド
npm run check      # 一括実行（あれば）
```

## 検証ルール
実装完了後は検証コマンドを実行し、エラーがなくなるまで修正すること

## 受講生向けハンズオン中の振る舞い 4 ルール（v1.16.0〜・YOU MUST・全コンテキスト適用）

IMPORTANT: 受講生（GAS / Excel 経験者レベル・非エンジニア前提）にハンズオン手順を案内する文脈では**全タスク横断で以下 4 ルールを厳守**する。AI が「網羅的に案内する」自然な傾向で受講生の学習意欲が折れる事故を防ぐ。詳細とメタファーは `claude-md-template.md` の同名セクション参照。

### Rule 1: 1 メッセージ = 1 ステップ
- 5 ステップ手順を見つけたら最初の 1 ステップだけ表示し「この 1 つを完了したら報告してください」と明示
- 「Claude 作業」「受講生作業」「並行可」が 1 メッセージに混在しない

### Rule 2: 非エンジニアでもわかる言葉
- 専門用語の前に**1 文で言い換え**を添える（例: 「allowlist（許可リスト）」「Sensitive（秘密扱いフラグ）」）
- 手順は「画面の場所 → クリック → コピー → 貼る」レベルまで具体化
- コピペ対象は必ず `----ここから---- / ----ここまで----` で囲む

### Rule 3: 受講生作業 vs Claude 作業の境界明示
- 各ステップ冒頭に「**▶ あなたが作業 / ◀ Claude が作業**」マーカーを置く
- 並行作業を提案しない（授業中は同期優先）

### Rule 4: 必須最小限を判断して提示
- 機能を提示する前に「今この受講生に必須か / 将来必須か / 不要か」を分類
- 必須のみを最初の 1 メッセージに / 将来必須は予告のみ / 不要は省略
- プラン制約（Free / Pro 必須等）も**今の受講生のプランに合わせて判断**

**根拠**: T-62 Vercel デプロイ準備で 1 日 4 回再発（信頼度 3 🔴 確定）。「網羅的に案内する」「全部詰め込む」AI の自然な傾向は明示ルール化しないと再発する。

## 環境変数追加時は 3 箇所同期（v1.16.0〜・YOU MUST）

新しい環境変数を追加するときは、**`.env.local` だけ更新して終わらない**。以下 3 箇所を必ず同期する:

1. **`.env.local`**: 実値追記（受講生が別ターミナルで手動）
2. **`.env.example`**: ダミー値追記して git にコミット（引き継ぎ用変数一覧）
3. **Vercel ダッシュボード**: 本番デプロイ前に登録（Sensitive ON）

**根拠**: `.env.example` 漏れは引き継ぎ・別 PC 環境構築・pre-delivery-check のすべてで再発する構造的問題。新しい変数を追加する瞬間に同期を案内するのが唯一の予防策。
