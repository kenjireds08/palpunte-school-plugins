# Clear準備コマンド

コンテキストをクリアする前に、**詳細な**引き継ぎ用のメッセージをターミナルに出力します。

## 重要なルール

- **引き継ぎテキスト本体はファイル作成せず、ターミナルに直接出力する**
- ただし「学びの還元」だけは例外: 引き継ぎテキスト出力**前に** `/learn` スキルに従って `~/.claude/docs/best-practices.md` / `error-solutions.md` / `skill-health.md` に追記する（やり忘れで学びが消えないように）
- ユーザーがコピペして /clear 後に貼り付けられる形式にする
- **次のClaudeが困らないように、詳細に記載する**

## 手順0: 学びの有無をチェック（最初に必ず実行）

引き継ぎテキストを作る前に、セッション全体を振り返って **保存すべき新規の学びがあるか** を判定する。

### 判定フロー

1. **セッション内容を振り返る** - 以下の知見を発見したか？
    - エラーを2回以上試行して解決した（試行錯誤あり）
    - 新しいライブラリ・パターン・ツール・APIの使い方を発見
    - 上手くいかなかったアプローチがあった（アンチパターン）
    - スキル実行で品質低い・手動修正が必要だった
    - 案件固有のドメイン知識を発見

2. **該当なし** → **何もしない**。引き継ぎテキストの「💾 自動保存した学び」セクションには **「なし」** とだけ記載して終了。ファイル読み込みも追記もしない。

3. **該当あり** → 既存ファイル（`~/.claude/docs/best-practices.md` / `error-solutions.md` / `skill-health.md`）を grep で重複チェック → 既存と重複していれば追記しない → **本当に新規の学びだけ**追記する。

### 追記先

| 検出する知見 | 追記先 |
|------------|--------|
| エラーを2回以上試行して解決した | `~/.claude/docs/error-solutions.md` |
| 新しいライブラリ・パターン・ツール・APIの使い方を発見 | `~/.claude/docs/best-practices.md` |
| 上手くいかなかったアプローチ（アンチパターン） | `~/.claude/docs/best-practices.md`（注意点・落とし穴） |
| スキル実行で品質低い・手動修正が必要だった | `~/.claude/docs/skill-health.md` |

詳細フォーマット・重複排除ルールは `/learn` スキルを参照。

### 出力ルール

- 実際に追記したものだけを「💾 自動保存した学び」セクションに記載する
- 何も追記しなかった場合は「なし」とだけ記載
- **「念のため空ファイル touch」「テンプレ追記」のような無駄な書き込みは絶対にしない**

## 出力フォーマット

## 詳細記載のガイドライン

### なぜ詳細が必要か
- /clear 後のClaudeは**何も覚えていない**
- 省略された情報は**失われる**
- 詳細であればあるほど、スムーズに作業を再開できる

### 特に詳しく書くべきこと
1. **ファイルパス**: 必ず絶対パスで記載
2. **意思決定の理由**: なぜその選択をしたか
3. **試行錯誤の過程**: 何を試して何がダメだったか
4. **現在の状態**: ビルド・テスト・サーバーの状態
5. **次のアクション**: 具体的に何をすべきか

### 省略してはいけないこと
- 作成したファイルの一覧
- 変更したファイルの一覧
- 技術的な決定事項
- エラーや問題が発生した場合はその詳細

## 手順

1. 今回の会話内容を**全て**振り返る
2. 上記フォーマットで**詳細な**引き継ぎメッセージを作成
3. ターミナルに直接出力する（ファイル作成禁止）
4. ユーザーに「コピーして /clear 後に貼り付けてください」と伝える
