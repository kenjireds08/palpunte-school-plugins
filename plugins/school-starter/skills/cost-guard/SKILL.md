# cost-guard スキル — AI にお金を使わせる前の安全確認

## このスキルの目的

**AI の自動化で、寝ている間に想定外の請求が発生する事故を防ぐ。**

実際に、AI の自動レビューが暴走して **1 日で 150 万円** の請求が出た事例がある（2026年5月）。
特別に無茶をしたわけではなく、「push するたびに AI がレビューする」「AI が直して push する」を
組み合わせただけで、AI 同士が無限ループに入った。

このスキルは、そういう仕組みを作る**前**に止まって、4 つだけ確認する。

## 発動したら、まずこれを伝える

IMPORTANT: 最初に必ず「**今から作ろうとしているものは、どちらのお財布を使うか**」をはっきりさせる。
ここが分かっていないと、あとの話が全部ぼやける。

| | 定額サブスク | 従量課金（使った分だけ請求） |
|---|---|---|
| 例 | Claude Code 本体（Max / Pro プラン） | API キーを使う処理・自動レビューサービス・画像生成・GitHub Actions |
| 増えるもの | **増えない**（上限に達したら止まるだけ） | **青天井**。動いた回数だけ請求される |
| 寝ている間の事故 | 起きない | **起きる** |

**今この画面で自分が Claude Code に話しかけている分は、定額のほうなので暴走しない。**
危ないのは、これから作る「自動で動く仕組み」のほうだと明確に伝える。

## 確認する 4 項目（1 つずつ・まとめて出さない）

以下を **1 メッセージ 1 項目**で確認する。全部を一度に並べない。

### ① 上限を先に決める（最優先・作る前にやる）

▶ ユーザーが作業:
- 使うサービスの管理画面で **上限金額（Spend Limit / Usage limit）を設定**してもらう
- 「月にいくらまでなら払っていいか」を先に決めてから作る

金額の目安を聞かれたら、**その人が「これなら諦められる」と言える額**を勧める。
上限が高すぎると、気付いたときには手遅れになる（前述の事故も、上限が高すぎて手前で止まらなかった）。

主な設定場所:
- Anthropic / OpenAI の API → コンソールの Billing → Usage limits
- Vercel → プロジェクト設定の Spend Management
- GitHub Actions → Settings → Billing → Spending limit

### ② 動くきっかけ（トリガー）を絞る

◀ Claude が作業（設計を見直す）:
- 「保存するたび」「push するたび」「アクセスされるたび」は**回数が読めない** → 避ける
- 「1 日 1 回」「ボタンを押したときだけ」のように、**1 日の最大回数が計算できる形**にする
- 作る前に「これは 1 日最大何回動くか」を口に出して確認する。答えられないなら設計をやり直す

### ③ AI に最後まで任せない

◀ Claude が作業:
- AI が「判断 → 修正 → 保存 → もう一度自分で確認」まで回る形にしない
- **AI は提案まで。実行の引き金は人間が引く**
- 前述の事故は、まさにこの輪が閉じたことで起きた

### ④ 終わったら止める

▶ ユーザーが作業:
- 検証が終わった自動実行は**その日のうちに止める**（動かしっぱなしにしない）
- 作った直後に「止め方」も一緒にメモしておく。止め方が分からない仕組みは作らない

止め方を必ずセットで案内する（例: `crontab -e` で行を消す / GitHub Actions の workflow を無効化する / launchd なら `launchctl unload`）。

## 作ったあとの声かけ

自動実行の仕組みを作り終えたら、Claude から必ず一言添える:

> この仕組みは、止めるまで動き続けます。今日は動作確認だけして、
> 使い終わったら止めておきましょう。止め方は〜です。

そして**翌日、最初に請求額を確認してもらう**よう促す。1 日目に気付けば被害は 1 日分で済む。

## やってはいけない案内

- 「無料枠があるので大丈夫です」で終わらせる（無料枠を超えた瞬間に課金が始まる）
- 上限設定の話を後回しにして、先に仕組みを作る
- 「たぶん安いと思います」と根拠なく言う → **1 回あたりの単価を調べてから答える**
