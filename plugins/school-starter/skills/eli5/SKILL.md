# eli5 — 何も知らない人向けの図解HTML

出典: Anthropic の Thariq Shihipar 氏（@trq212）が公開した eli5 プラグイン（`anthropics/claude-plugins-community` / MIT）を、日本語運用向けに書き直したもの。本家のスキル本文は英語1文のみ。

**Topic: $ARGUMENTS**

## やること

指定されたトピックを、**その分野の前提知識がゼロの人**に向けて説明する HTML ファイルを1枚作り、`open -a "Google Chrome"` で開く。

## 守ること

### 1. ライトテーマ固定（例外なし）
- `color-scheme: light only` を書く
- `@media (prefers-color-scheme: dark)` と `:root[data-theme="dark"]` は**書かない**
- 理由: 説明資料をダークに追従させると、相手の環境で崩れて読めなくなる事故が起きるため

### 2. 図が主役・文字は脇役
- **図を最低1つ、できれば2〜3つ入れる**。文章だけの HTML なら、このスキルを使う意味がない
- 図は**インライン SVG か CSS のボックス図**で描く。**mermaid・外部 CDN は使わない**（ローカルの `file://` で開くため描画されない・オフラインで死ぬ）
- 1つの図に詰め込まない。「登場人物」「流れ」「前と後」で分ける
- 図には必ず日本語のラベルを振る

### 3. 言葉を減らす
- 1文は短く。専門用語が出たら、その場で1行で言い換える
- 箇条書きの羅列で埋めない。見出し＋図＋2〜3文が基本のリズム
- 「〜という概念があります」で終わらせず、**それで何が変わるのか**まで書く

### 4. たとえ話は「業務のたとえ」まで
- 幼稚なたとえ（「API 呼び出しは車で友達の家に運転する感じ」等）に逃げない。本家でも実際に苦情が出ている失敗パターン
- たとえるなら、読み手が実際にやっている業務にたとえる

### 5. 分からないことは分からないと書く
- 推測で埋めない。調べていない箇所は「未確認」と明記する

## 出力先

- 一時的な理解用: プロジェクト外の一時フォルダ
- 残す価値があるもの（クライアント説明・引き継ぎ資料）: そのプロジェクトの `docs/` 配下に置き、ファイル名を内容に合わせる

作ったら**必ずブラウザで開いて見せる**。パスを伝えるだけで終わらせない。

## 関連

- 実装プランの「判断用 HTML 要約」とは用途が違う（あちらは発注者が判断するための1枚。ひな形は `references/plan-summary-template.html`）。図の描き方はこのスキルの記述を共通の基準として使う

## 図のスタイル（ちーけんさん指定・2026-08-22）

見本の型をそのまま使う。**この型で描くこと自体がこのスキルの価値**なので崩さない。

### 全体の型
1. **番号付きステップ**で章立てする。見出しは大きな数字（アクセント色）＋短い断定文。「1. ロボットは1体。耳は2つ。ノートは1冊。」のように**体言止め・短文の並列**が効く
2. 各ステップの本文＝**図が1つ**。図は薄いグレーの枠線＋角丸のパネルに入れ、パネル内は白〜ごく薄い背景
3. **図の直下に、地の文で一言だけ添える**（小さめ・グレー）。図の説明ではなく、**その図から何が言えるか**を書く。例:「これは眠らない。あとで効いてくる」
4. ステップ間はたっぷり余白を取る。詰めない

### 図の中身
- **登場人物・モノを絵記号で置く**: 人＝丸＋肩の線、システム＝ウィンドウ枠（左上に3つの丸）、DB＝円柱、外部サービス＝そのサービス色のカード、時間や定期実行＝時計、曖昧なもの（クラウド等）＝点線の雲
- **箱の中にラベルを2段で書く**: 上段＝日本語の呼び名（太字・黒）、下段＝実体（小さくグレー。URL・API パス・テーブル名など）
- **矢印には必ず動詞のラベルを振る**。「保存する」「読み書きする」「通知する」。矢印だけ引いて終わらせない
- **線種で意味を分ける**: 実線＝主な流れ、点線＝補助・条件付き・外部要因
- 双方向なら両端に矢印を付ける

### 配色
- 背景は白〜ごく薄いグレー、線と文字はグレー〜黒の**モノトーンが基本**
- **アクセント色は1色だけ**（インディゴ系）。番号・主役のアイコン・最重要の1ノードにだけ使う
- 外部サービスを描くときだけ、そのサービスのブランド色を使ってよい（Discord の紫など）
- 色で分類しない。**色を増やすと途端に安っぽくなる**

### 技術面
- **インライン SVG で描く**（`<svg>` を HTML に直接書く）。mermaid・外部 CDN・画像ファイル参照はしない
- `viewBox` を付けて `max-width: 100%; height: auto;` で縮む状態にする
- SVG 内の文字は 12〜14px 相当。小さくしすぎない
- 図が横に長くなるときは `overflow-x: auto` の箱に入れる（ページ全体を横スクロールさせない）

## 絵記号の語彙（品質はここで決まる・必ず使う）

**同じ長方形を並べただけの図はクオリティが出ない。** 登場するモノは、一目で種類が分かる記号で描き分ける。以下をそのまま使ってよい（`stroke:#b9b9b4; fill:#fff; stroke-width:1.5`）。

| 描くもの | 記号 | SVG の骨子 |
|---|---|---|
| Web サイト・画面・フォーム | 窓枠（左上に小さい丸3つ＋横線1本） | `<rect rx="6">` ＋ `<circle r="3">`×3 ＋ 仕切りの `<line>` |
| データベース・保存先 | 円柱 | `<ellipse>`（上面）＋ `<path>`（側面）＋ `<ellipse>`（底） |
| 定時実行・タイマー | 時計 | `<circle>` ＋ 針の `<line>`×2。脇に「8:00」等 |
| クラウド・外部の曖昧なもの | 点線の雲 | `<path>` の雲形に `stroke-dasharray="4 4"` |
| 人（担当者・利用者・受講生） | 丸＋肩の弧 | `<circle>` ＋ `<path d="M..a..0 0 1 ..">` |
| 外部サービス（Discord・LINE 等） | そのブランド色で塗った角丸カード | `<rect rx="8" fill="#5865F2">` ＋ 白文字 |
| 自動で動くもの・Bot | ロボット顔（角丸四角＋目2つ＋アンテナ） | `<rect rx="8">` ＋ `<circle>`×2 ＋ 上に `<line>`＋`<circle>` |
| ファイル・書類 | 角折れの紙 | `<path>` で右上を欠いた四角 |

### 構図
- **一列に並べない**。中央に主役を置いて周りから矢印を集める、上下2段に分ける、など**場面として組む**
- 主役だけ少し大きく描く。全部同じ大きさにしない
- **図の外側の余白に小さな注記を置く**と密度が上がる。例: 図の右に「カード＝タイトル＋画像＋日時＋ボタン2つ」のような定義書き（`.fig-sub` サイズ）
- 1つの図に**5〜8個**のモノを置くのが読みやすさの上限。それを超えるなら図を分ける

### 作ったら必ず自分で見る

SVG のラベルは、書いた時点では重なりに気づけない。**HTML を保存したら必ず一度スクリーンショットを撮って自分で確認する**（`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --screenshot=out.png --window-size=1440,900 "file://<絶対パス>"`）。矢印のラベルが箱に重なる／図の外へはみ出すのが最も多い崩れ方。直すまで人には見せない。
